# 2. Antes de comparar herramientas: ¿qué es MPC?

## 2.1 Idea básica

Multi-Party Computation permite que varias partes realicen un cálculo utilizando información privada sin que necesariamente tengan que revelar esa información entre ellas.

La idea puede entenderse de la siguiente manera.

Supongamos que tres organizaciones quieren calcular un resultado usando información confidencial:

- Municipalidad A tiene un dato secreto.
- Institución B tiene otro dato.
- Servidor C participa en el cálculo.

Un sistema tradicional podría hacer esto:

```text
Municipalidad A ── dato original ──► Servidor
Institución B   ── dato original ──► Servidor
                              │
                              ▼
                         procesamiento
                              │
                              ▼
                           resultado
```

El problema es que el servidor llega a conocer los datos originales.

Con MPC se intenta transformar el proceso en algo como:

```text
              fragmento 1
Dato privado ─────────────► Servidor MPC 1

              fragmento 2
             ─────────────► Servidor MPC 2

              fragmento 3
             ─────────────► Servidor MPC 3
```

Cada servidor recibe solamente información parcial.

Los servidores cooperan para realizar operaciones sobre esos fragmentos y obtener únicamente el resultado que se haya autorizado revelar.

---

# 3. Concepto fundamental: Secret Sharing

La mayoría de herramientas investigadas se apoyan, directa o indirectamente, en técnicas de **secret sharing**.

## 3.1 Ejemplo simplificado

Supongamos que el valor secreto es:

```text
100
```

En lugar de enviar el número `100` completo a un servidor, se puede dividir conceptualmente en varios fragmentos:

```text
Parte 1 = 37
Parte 2 = 81
Parte 3 = -18
```

La suma es:

```text
37 + 81 - 18 = 100
```

Cada servidor obtiene solamente una parte.

```text
Servidor A conoce 37
Servidor B conoce 81
Servidor C conoce -18
```

Ninguno conoce individualmente el valor `100`.

> Este ejemplo es únicamente conceptual. Las implementaciones reales utilizan aritmética modular, campos finitos, números aleatorios y protocolos criptográficos específicos.

---

# 4. ¿Cómo pueden calcular algo si nadie conoce el dato completo?

Esta es precisamente la función del protocolo MPC.

Algunas operaciones son relativamente sencillas.

Por ejemplo, si dos valores secretos están compartidos:

```text
A = A1 + A2 + A3
B = B1 + B2 + B3
```

los servidores pueden sumar localmente:

```text
Servidor 1: A1 + B1
Servidor 2: A2 + B2
Servidor 3: A3 + B3
```

Los fragmentos resultantes representan:

```text
A + B
```

sin reconstruir necesariamente `A` ni `B`.

Sin embargo, operaciones como:

- multiplicación;
- división;
- comparación;
- máximo;
- mínimo;
- igualdad;
- convoluciones;
- activaciones de redes neuronales;

normalmente requieren protocolos adicionales y comunicación entre las partes.

Por eso **MPC es considerablemente más costoso que ejecutar el mismo algoritmo normalmente**.

# 5. Conceptos técnicos necesarios para entender los frameworks

## 5.1 Party

Una **party** es una entidad que participa en el protocolo MPC.

Puede ser:

- un servidor;
- una institución;
- una Raspberry Pi;
- un cliente;
- una máquina virtual.

Ejemplo:

```text
Party 0 → Municipalidad
Party 1 → Universidad
Party 2 → Servidor independiente
```

---

## 5.2 Honest majority

Significa que el protocolo supone que la mayoría de las partes no están comprometidas.

Por ejemplo, con tres participantes:

```text
Party 1
Party 2
Party 3
```

un protocolo puede asumir que como máximo uno se comportará incorrectamente o intentará aprender información privada.

---

## 5.3 Dishonest majority

Algunos protocolos permiten proteger los datos incluso si la mayoría de participantes está comprometida.

Normalmente esto ofrece garantías más fuertes, pero también aumenta:

- cantidad de operaciones criptográficas;
- comunicación;
- consumo de CPU;
- tiempo de ejecución.

---

## 5.4 Adversario semi-honesto

También se llama **passive adversary**.

La parte:

1. ejecuta correctamente el protocolo;
2. pero intenta analizar toda la información que recibe para descubrir datos privados.

Ejemplo:

```text
El servidor sigue las instrucciones,
pero guarda todos los mensajes e intenta inferir el secreto.
```

---

## 5.5 Adversario malicioso

También se llama **active adversary**.

La parte puede:

- enviar valores falsos;
- modificar mensajes;
- saltarse pasos;
- intentar alterar el resultado;
- intentar extraer datos privados.

Protegerse frente a participantes maliciosos suele ser más costoso.

---

# 6. Circuitos aritméticos y circuitos booleanos

Los frameworks MPC suelen convertir los cálculos a operaciones criptográficas relativamente básicas.

## 6.1 Circuitos aritméticos

Trabajan principalmente con:

```text
suma
resta
multiplicación
```

Son útiles para:

- matrices;
- estadísticas;
- Machine Learning;
- convoluciones;
- operaciones numéricas.

Para Computer Vision suelen ser muy importantes.

---

## 6.2 Circuitos booleanos

Trabajan principalmente con bits:

```text
AND
OR
XOR
NOT
```

Pueden ser útiles para:

- comparaciones;
- lógica condicional;
- operaciones binarias.

---

# 7. ¿Por qué esto importa para Computer Vision?

Una red neuronal normal puede ejecutar millones o miles de millones de operaciones.

Por ejemplo, una capa convolucional realiza muchas operaciones similares a:

```text
pixel × peso
```

seguidas de sumas.

En ejecución normal esto es rápido porque la CPU, GPU o acelerador realiza estas operaciones directamente.

En MPC una multiplicación puede requerir:

```text
CPU local
+
criptografía
+
comunicación de red
+
sincronización con otras parties
```

Por lo tanto:

```text
una multiplicación normal
≠
una multiplicación MPC
```

La segunda es mucho más costosa.

---

# 8. Consideración crítica para el proyecto: MPC no procesa "un MP4" directamente

Esta es una distinción muy importante.

Las herramientas MPC analizadas normalmente trabajan con:

- enteros;
- bits;
- números de punto fijo;
- arreglos;
- matrices;
- tensores;
- valores secret-shared.

No trabajan conceptualmente con:

```text
video.mp4
```

como una unidad criptográfica de alto nivel.

Antes del MPC habría que transformar el contenido en datos procesables.

Por ejemplo:

```text
video.mp4
   │
   ▼
decodificación
   │
   ▼
frames
   │
   ▼
matrices de píxeles
   │
   ▼
representación numérica
   │
   ▼
secret sharing / MPC
```

---

# 9. Tamaño del problema al trabajar con video

Un frame RGB de 1920 × 1080 contiene aproximadamente:

```text
1920 × 1080 × 3
= 6 220 800 valores de color
```

Eso significa más de seis millones de componentes por frame si se trabaja directamente con RGB.

A 30 frames por segundo:

```text
6 220 800 × 30
≈ 186 millones de componentes por segundo
```

Esto no significa exactamente 186 MB/s en MPC, porque la representación criptográfica puede usar mucho más que un byte por valor.

El punto importante es:

> proteger cada píxel individualmente mediante MPC puede generar un volumen de cálculo y comunicación extremadamente alto.

Por esto, la evaluación del proyecto debe distinguir entre:

### Caso A — MPC sobre datos pequeños

Ejemplos:

- conteo de vehículos;
- estadísticas;
- coordenadas;
- velocidades;
- resultados de detección;
- identificadores;
- vectores pequeños.

Este escenario es relativamente viable.

### Caso B — MPC sobre el modelo completo de Computer Vision

Ejemplos:

- ingresar todos los píxeles como datos secretos;
- ejecutar una red neuronal completa dentro del MPC;
- realizar convoluciones y comparaciones sin revelar los frames.

Este escenario es considerablemente más complejo.

# 12. Herramienta 1 — Sharemind MPC

## 12.1 ¿Qué es Sharemind?

Sharemind es una plataforma de computación que permite desarrollar aplicaciones que trabajan sobre datos privados utilizando técnicas de secure multiparty computation.

Su arquitectura clásica utiliza **tres servidores de cálculo independientes**.

```text
                    ┌───────────────┐
                    │ MPC Server 1  │
                    └───────────────┘
                          ▲
                          │ share 1
                          │
Dato privado ─────────────┼─────────────
                          │
                          │ share 2
                          ▼
                    ┌───────────────┐
                    │ MPC Server 2  │
                    └───────────────┘

                          │ share 3
                          ▼
                    ┌───────────────┐
                    │ MPC Server 3  │
                    └───────────────┘
```

La documentación oficial describe su motor de cálculo cifrado utilizando un esquema de **secret sharing aditivo de tres partes**.

---

# 13. Modelo de seguridad de Sharemind

En la configuración `shared3p`, los datos se dividen entre tres servidores.

Una propiedad importante es que se presupone que los servidores son administrados por organizaciones independientes y que no coluden.

La arquitectura típica sería:

```text
Servidor 1 → Municipalidad
Servidor 2 → TEC
Servidor 3 → Organización independiente
```

Cada servidor conserva solamente una parte de los datos.

La confidencialidad depende de mantener las condiciones del protocolo y el supuesto de no colusión.

---

# 14. Lenguaje SecreC

Las aplicaciones Sharemind utilizan un lenguaje llamado **SecreC**.

SecreC tiene una sintaxis similar a C.

Ejemplo conceptual:

```text
public int cantidad;

private int valor;
```

La característica importante es que el lenguaje diferencia entre:

```text
datos públicos
```

y

```text
datos protegidos
```

El compilador controla cómo se utilizan.

Esto ayuda a evitar errores donde un programador publique accidentalmente información secreta.

---

# 15. ¿Por qué Sharemind creó un lenguaje propio?

La documentación de SecreC explica que trabajar con MPC requiere conocer en todo momento si un dato:

```text
es público
```

o

```text
es privado
```

Un lenguaje tradicional como Python o Java no incorpora ese concepto directamente en su sistema de tipos.

SecreC intenta convertirlo en parte del lenguaje.

Esto permite detectar situaciones como:

```text
dato privado → dato público
```

cuando esa conversión no está permitida.

---

# 16. Flujo de ejecución en Sharemind

De manera simplificada:

```text
1. Se escribe un programa en SecreC
            │
            ▼
2. El programa se compila
            │
            ▼
3. Se genera bytecode
            │
            ▼
4. Los servidores Sharemind ejecutan el bytecode
            │
            ▼
5. Los servidores operan sobre secret shares
            │
            ▼
6. Se publica únicamente el resultado autorizado
```

# 22. Sharemind y Raspberry Pi

La documentación oficial encontrada **no indica explícitamente que la plataforma completa de Sharemind MPC esté probada en Raspberry Pi**.

# 25. Herramienta 2 — MP-SPDZ

## 25.1 ¿Qué es MP-SPDZ?

MP-SPDZ es un framework de investigación y desarrollo para secure multiparty computation.

Una de sus características más importantes es que implementa **muchos protocolos MPC diferentes**.

Esto permite utilizar el mismo programa de alto nivel y probar diferentes modelos de seguridad.

Ejemplo:

```text
mismo cálculo
    │
    ├──► Rep3
    ├──► MASCOT
    ├──► SPDZ2k
    ├──► Semi2k
    ├──► Shamir
    ├──► Yao
    └──► BMR
```

Esto lo convierte en una excelente herramienta para investigación y benchmarking.

---

# 26. Arquitectura interna de MP-SPDZ

Su funcionamiento puede resumirse en dos etapas.

```text
Código MPC de alto nivel
        │
        ▼
   compilador Python
        │
        ▼
      bytecode
        │
        ▼
Virtual Machine C++
        │
        ▼
 protocolo MPC
        │
        ▼
 comunicación entre parties
```

Esto significa que Python se utiliza principalmente para describir el cálculo.

La ejecución criptográfica pesada ocurre en una máquina virtual implementada en C++.

---

# 27. Ejemplo simple de MP-SPDZ

Un entero secreto se representa con el tipo:

```python
sint
```

Ejemplo:

```python
a = sint.get_input_from(0)
b = sint.get_input_from(1)

resultado = a + b

print_ln("%s", resultado.reveal())
```

## Explicación paso a paso

### Línea 1

```python
a = sint.get_input_from(0)
```

Party 0 aporta un valor privado.

### Línea 2

```python
b = sint.get_input_from(1)
```

Party 1 aporta otro valor privado.

### Línea 3

```python
resultado = a + b
```

La suma se realiza utilizando representación secreta.

### Línea 4

```python
resultado.reveal()
```

El resultado se reconstruye.

Este último paso es crítico.

En MPC se debe controlar cuidadosamente **qué valores se revelan**.

---

# 28. Protocolos disponibles en MP-SPDZ

MP-SPDZ soporta numerosos modelos.

Entre ellos:

### MASCOT

- seguridad frente a adversarios maliciosos;
- soporta dishonest majority;
- fuerte seguridad;
- mayor costo computacional.

### SPDZ2k

- operaciones módulo `2^k`;
- seguridad maliciosa;
- útil para aritmética similar a enteros de máquina.

### Semi2k

- versión semi-honesta;
- elimina verificaciones necesarias para seguridad maliciosa;
- puede ser más rápida.

### Rep3

- secret sharing replicado de tres partes;
- versiones semi-honestas y maliciosas;
- muy interesante para arquitecturas con tres servidores.

### Shamir

- basado en Shamir Secret Sharing;
- útil cuando existe honest majority.

### Yao

- garbled circuits;
- especialmente utilizado en computación segura de dos partes.

---

# 29. ¿Por qué tener tantos protocolos es útil?

Porque no existe un único protocolo óptimo.

Por ejemplo:

```text
máxima seguridad
        │
        └── puede requerir más CPU

baja latencia
        │
        └── puede requerir más confianza

pocas parties
        │
        └── puede cambiar el protocolo ideal

muchas comparaciones
        │
        └── puede favorecer circuitos booleanos

muchas matrices
        │
        └── puede favorecer circuitos aritméticos
```

MP-SPDZ permite experimentar con estas combinaciones.

---

# 30. Seguridad configurable

Esta es posiblemente la mayor ventaja académica de MP-SPDZ.

El equipo puede ejecutar la misma prueba con:

```text

```

y luego con:

```text
malicious
```

para medir cuánto aumenta:

- CPU;
- RAM;
- tráfico;
- tiempo.

Eso permite documentar el costo real de aumentar la seguridad.

# 33. MP-SPDZ y Raspberry Pi

### Ventaja

El soporte ARM64 está explícitamente documentado.

### Problema

MP-SPDZ tiene muchas dependencias.

Compilar todo el framework puede consumir:

- tiempo;
- CPU;
- almacenamiento;

# 40. ¿Por qué reducir rondas de comunicación es importante?

Supongamos que una operación requiere enviar mensajes:


Por eso los frameworks intentan transformar:

```text
operación
mensaje
operación
mensaje
operación
mensaje
```

en algo más parecido a:

```text
muchas operaciones
        │
        ▼
un conjunto de mensajes
```

# 61. ¿Qué es MPyC?

MPyC significa aproximadamente:

```text
Multi-Party Computation in Python
```

Permite escribir programas MPC utilizando una API muy similar a Python normal.

Ejemplo conceptual:

```python
from mpyc.runtime import mpc

secint = mpc.SecInt()

x = secint(10)
y = secint(20)

resultado = x + y
```

El runtime se encarga de la comunicación necesaria entre las parties.

---

# 62. Modelo de seguridad de MPyC

MPyC utiliza principalmente **Shamir threshold secret sharing**.

La documentación indica protección frente a adversarios pasivos controlando menos de la mitad de las partes.

Matemáticamente:

```text
t < m / 2
```

donde:

```text
m = cantidad total de parties
t = parties comprometidas toleradas
```

Ejemplo:

```text
m = 3
t = 1
```

Eso significa que con tres parties puede tolerarse un adversario pasivo.

La documentación indica:

```text
Python 3.10+
```

como requisito principal.

No requiere obligatoriamente:

- Boost;
- OpenSSL;
- libsodium;
- CMake;
- compilador C++.

Esto simplifica mucho la instalación.

```text
¿qué operación exacta queremos proteger con MPC?
```

Por ejemplo, no es equivalente proteger:

```text
100 conteos de vehículos
```

que proteger:

```text
6 millones de píxeles por frame
```

La herramienta ideal puede cambiar completamente según la carga.

# 95. Resumen ejecutivo para exposición

Si se necesita explicar el resultado en pocos minutos:

> MPC permite dividir información sensible entre varias partes para que puedan realizar cálculos sin que una sola parte tenga acceso a todos los datos originales. Se investigaron Sharemind, MP-SPDZ y JIFF, y se añadió MPyC por su especial compatibilidad con Raspberry Pi. MP-SPDZ es el framework más completo porque soporta gran cantidad de protocolos, ARM64 y algunas operaciones de Machine Learning, por lo que es el candidato principal para investigación. Sin embargo, tiene muchas dependencias y puede consumir bastantes recursos. MPyC es una biblioteca Python mucho más ligera y su documentación menciona explícitamente Raspberry Pi, por lo que debería utilizarse como segundo candidato de prueba. JIFF es muy conveniente para aplicaciones web, pero está menos orientado a Computer Vision. Sharemind ofrece una arquitectura institucional robusta de tres servidores, aunque su plataforma completa es más pesada. La decisión final debe tomarse realizando benchmarks con el mismo cálculo en cada herramienta.

# 98. Conclusión general

No existe una herramienta MPC que sea simultáneamente:

```text
la más segura
+
la más rápida
+
la más ligera
+
la más fácil
+
la mejor para Computer Vision
```

Cada opción representa compromisos.

Para este proyecto:

```text
MP-SPDZ
```

es actualmente el mejor candidato para investigar en profundidad la implementación MPC debido a su flexibilidad, soporte de múltiples protocolos, soporte ARM64 y capacidades relacionadas con Machine Learning.

Por otro lado:

```text
MPyC
```

debe considerarse seriamente como alternativa para hardware limitado porque posee una instalación mucho más liviana y compatibilidad explícita con Raspberry Pi.

La decisión definitiva no debería realizarse únicamente con documentación.

El siguiente paso técnicamente correcto es realizar un benchmark controlado sobre Raspberry Pi y computadora convencional utilizando exactamente la misma operación MPC.

De esta manera el equipo podrá responder con evidencia:

```text
¿Cuánto RAM utiliza?
¿Cuánto CPU utiliza?
¿Cuánto tarda?
¿Cuánto tráfico genera?
¿Qué seguridad ofrece?
¿Qué tan difícil es integrarlo?
```

y seleccionar la tecnología más adecuada para el sistema final.
